# 集成测试文档

## 📋 概述

本文档说明如何基于单元测试创建和运行集成测试。本项目包含**8个单元测试类**和**3个集成测试类**，展示了从单元测试到集成测试的完整测试策略。

---

## 🎯 测试架构

### 测试金字塔

```
        /\
       /  \  系统测试（E2E）
      /____\
     /      \  集成测试（3个类，21个测试用例）← 本次创建
    /________\
   /          \  单元测试（8个类，参数化测试）← 已有
  /____________\
```

### 单元测试 vs 集成测试对比

| 特性 | 单元测试 | 集成测试 |
|------|---------|---------|
| **测试范围** | 单个类/方法 | 多个组件协作 |
| **依赖处理** | Mock所有依赖 | 使用真实依赖 |
| **Spring容器** | 不启动 | 完整启动 |
| **数据库** | Mock | H2内存数据库 |
| **HTTP层** | 不测试 | MockMvc测试 |
| **运行速度** | 快（毫秒级） | 慢（秒级） |
| **注解** | `@ExtendWith(MockitoExtension.class)` | `@SpringBootTest` |

## 🔄 单元测试到集成测试的映射

### 1. 用户认证模块

#### 单元测试（UserServiceUnitTest.java）
```java
@ExtendWith(TestResultLogger.class)
class UserServiceUnitTest {
  private final UserMapper userMapper = mock(UserMapper.class);  // Mock
  private final UserService service = new UserService(userMapper, ...);
  
  @ParameterizedTest
  @MethodSource("registerSuccessCases")
  void registerTrimsFieldsEncodesPasswordAndInsertsUser(...) {
    when(userMapper.countByUsername(username)).thenReturn(0L);  // Mock行为
    User result = service.register(request);
    verify(userMapper).insert(captor.capture());  // 验证Mock调用
  }
}
```

#### 集成测试（UserAuthenticationIntegrationTest.java）
```java
@SpringBootTest  // 启动完整Spring容器
@AutoConfigureMockMvc
@Transactional
class UserAuthenticationIntegrationTest {
  @Autowired
  private MockMvc mockMvc;  // 真实的MVC环境
  
  @Autowired
  private UserRepository userRepository;  // 真实的Repository
  
  @Test
  void testCompleteAuthenticationFlow() throws Exception {
    // 1. 注册 - 真实HTTP请求
    mockMvc.perform(post("/api/register")
            .content(registerJson))
        .andExpect(status().isOk());
    
    // 2. 登录 - 真实HTTP请求
    mockMvc.perform(post("/api/login")
            .content(loginJson))
        .andExpect(status().isOk());
    
    // 3. 验证数据库 - 真实数据库查询
    assertTrue(userRepository.existsByUsername("test"));
  }
}
```

**关键区别：**
- ✅ 单元测试：Mock所有依赖，只测试Service层逻辑
- ✅ 集成测试：真实HTTP → Controller → Service → Repository → Database

```java
@ParameterizedTest(name = "[{index}] {0}")
@MethodSource("registerRejectCases")

                                 boolean verificationResult, long usernameCount, long emailCount) {
  when(emailVerificationService.verify(...)).thenReturn(verificationResult);
  when(userMapper.countByUsername(...)).thenReturn(usernameCount);
  
  assertThrows(ResponseStatusException.class, () => service.register(request));
}

static Stream<Arguments> registerRejectCases() {
  return Stream.of(
    Arguments.of("verification code is invalid", registerRequest(...), false, 0L, 0L),
    Arguments.of("username already exists", registerRequest(...), true, 1L, 0L),
    Arguments.of("email already exists", registerRequest(...), true, 0L, 1L)
  );
}
```

## 📚 总结

### 单元测试的价值

1. **快速反馈** - 毫秒级运行
2. **精确定位** - 准确找到问题所在
3. **文档作用** - 展示如何使用API
4. **重构保障** - 安全重构代码

### 集成测试的价值

1. **真实场景** - 测试完整业务流程
2. **发现集成问题** - 组件协作问题
3. **接近生产** - 使用真实依赖
4. **端到端验证** - HTTP到数据库

### 测试策略建议

```
70% 单元测试  - 快速、精确、大量
20% 集成测试  - 关键流程、真实场景
10% E2E测试   - 用户视角、完整系统
```
